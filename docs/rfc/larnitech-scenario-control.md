# Безопасный запуск allowlisted-сценариев Larnitech

## Контекст и границы

Локальная панель Raspberry Pi должна запускать только заранее исследованные
сценарии Larnitech. Произвольные API2-адреса, поля `status`, отдельные реле,
шторы, свет и кондиционер через HTTP API не экспортируются.

Содержимое семи сценариев получено read-only через LT Setup 4.150 до первого
управляющего запроса и описано в
[инвентаризации](../inventory/larnitech-scenarios.md). Физический запуск не
входит в статическую проверку и требует осознанного подтверждения на объекте.

## Решение

Gateway содержит неизменяемый реестр адреса, имени, краткого действия и уровня
риска. Для запуска одновременно требуются:

1. глобальный флаг `LARNITECH_SCENARIO_CONTROL_ENABLED=true`;
2. точный адрес в `LARNITECH_SCENARIO_ALLOWLIST`;
3. наличие в свежем API2 inventory сущности типа `script` с ожидаемым именем;
4. новый корректный `request_id`;
5. отсутствие выполняющегося запуска и истечение cooldown для адреса;
6. явное подтверждение пользователя в браузере.

Endpoint принимает только объект `{"addr":"…","request_id":"…"}` и сам
формирует единственную API2-команду `status-set` со `state=on`. После неё
gateway выполняет `status-get` и возвращает отдельные поля подтверждения.
Секреты, произвольные payload и содержимое credentials не журналируются.

## Риски и безопасное состояние

- При недоступном или устаревшем inventory новые команды запрещены.
- При ошибке авторизации, непредвиденном ответе или отсутствии подтверждения
  запрос завершается ошибкой и автоматически не повторяется.
- После перезапуска история cooldown не восстанавливается, но ни один сценарий
  не запускается автоматически.
- Остановка gateway полностью убирает новый канал управления; штатные LT Setup
  и физические органы управления сохраняются.
- API2-подтверждение не доказывает физический результат. UI и журнал явно это
  отмечают.

## Критерии приёмки

- [x] Тела семи сценариев извлечены read-only до запуска.
- [x] Реальные действия, вложенные сценарии, задержки и риски документированы.
- [x] Произвольный API2-адрес и произвольный `status` не проходят через HTTP API.
- [x] Есть статический реестр и отдельная runtime-allowlist.
- [x] Есть защита от параллельного, повторного и слишком частого запуска.
- [x] Запрос и результат журналируются без секретов.
- [x] UI требует подтверждение и показывает ограничение физической проверки.
- [x] Код объединён с итоговой версией параллельной настройки VAKIO.
- [x] На Raspberry Pi проверены disabled/deny-пути без запуска сценариев.
- [ ] Один разрешённый сценарий проверен физически после отдельного выбора
  пользователя и наблюдения на объекте.

## Откат

1. Установить `LARNITECH_SCENARIO_CONTROL_ENABLED=false` или очистить
   `LARNITECH_SCENARIO_ALLOWLIST`.
2. Перезапустить `smarthome-gateway` и убедиться, что кнопки заблокированы, а
   POST возвращает `403`.
3. При полном откате восстановить предыдущие `app.py`, `index.html` и nginx
   config из Git, проверить `nginx -t`, перезапустить gateway и reload nginx.

## Результаты проверки

- 2026-09-20 на Raspberry Pi прошли 14 unit-тестов gateway, включая мокированный
  `status-set`; реальный контроллер в тестах не получал управляющих команд.
- На установленной версии `GET /gateway/map` вернул `200`, 83 API2-канала,
  семь записей сценариев. После явного разрешения пользователя включены
  `scenario_control.enabled=true` и точный runtime-allowlist всех семи адресов:
  `315:246`, `315:250`, `407:246`, `407:247`, `407:248`, `456:46`, `456:47`.
- POST для известного `315:250` и произвольного `999:999` вернул `403`; в
  journal не появилось сообщения `Larnitech scenario requested`.
- В браузере одновременно проверены карточки VAKIO и семи сценариев Larnitech;
  до разрешения все семь кнопок сценариев были заблокированы.
- После включения allowlist gateway перезапущен и активен; runtime-снимок
  подтвердил `allowed=true` для всех семи адресов и cooldown 30 секунд.
- Физический запуск намеренно не выполнялся: разрешение allowlist не является
  подтверждением запуска конкретного сценария. В journal запросов запуска нет.
