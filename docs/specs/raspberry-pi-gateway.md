# Базовый шлюз Raspberry Pi

## Платформа

- Устройство: Raspberry Pi 3 Model B Plus Rev 1.4.
- ОС: Debian GNU/Linux 13 (trixie), `aarch64`.
- Проверенное ядро после перезагрузки: `6.18.50+rpt-rpi-v8`.
- Системный раздел: 29 GiB, занято около 6.7 GiB на дату проверки.
- Оперативная память: 905 MiB; swap: 904 MiB.
- Основное подключение к LAN: Wi-Fi.

## Установленные службы

| Компонент | Версия | Состояние | Назначение |
| --- | --- | --- | --- |
| Mosquitto | 2.0.21-1 | enabled, active | Локальный MQTT-брокер |
| Mosquitto clients | 2.0.21-1 | установлен | Диагностика MQTT |
| Nginx Light | 1.26.3-3+deb13u9 | enabled, active | HTTP и будущий reverse proxy |
| Python | 3.13.5-1 | установлен | Адаптер Larnitech/VAKIO |
| unattended-upgrades | 2.12 | enabled, active | Автоматические обновления безопасности |
| smarthome-gateway | Python-сервис | enabled, active | Карта Larnitech и ограниченный мост Larnitech ↔ VAKIO |
| gateway health timer | systemd | enabled, active | Контроль ресурсов каждые 5 минут |
| gateway backup timer | systemd | enabled, active | Ежедневный снимок несекретной конфигурации |

Автозапуск `NetworkManager-wait-online`, `smarthome-mqtt-firewall`,
`mosquitto`, `smarthome-gateway` и `nginx` явно включён. 20 сентября 2026 года
выполнен проверочный рестарт `smarthome-gateway`: после запуска MQTT,
Larnitech и VAKIO самостоятельно перешли в состояние `online`, мост
Larnitech ↔ VAKIO остался включён. Полная перезагрузка Raspberry Pi в рамках
этой проверки не выполнялась.

## Сетевые границы

- SSH слушает TCP `22` на LAN-интерфейсах.
- Nginx слушает TCP `80` на IPv4 и IPv6; опубликованы локальная панель,
  `/healthz`, `/gateway/healthz`, `/gateway/map`, ограниченные POST-маршруты
  `/gateway/vakio/command` и `/gateway/larnitech/scenario`.
- Каркас gateway слушает только `127.0.0.1:8080`.
- Mosquitto слушает TCP `1883` на LAN-адресе `192.168.1.183` с обязательной
  аутентификацией и ACL.
- Анонимный MQTT-доступ запрещён и фактически отклоняется брокером.
- MQTT-доступ из LAN предназначен только для VAKIO; учётные записи `vakio` и
  `gateway` ограничены ACL топиками `vakio/#`.

## Проверенное поведение

- `GET http://127.0.0.1/healthz` возвращает `200` и `ok`.
- `GET http://127.0.0.1/gateway/healthz` возвращает актуальную карту Larnitech,
  состояние MQTT/VAKIO, отдельные признаки управления VAKIO и сценариями.
- Анонимная MQTT-публикация завершается `Connection Refused: not authorised`.
- В Larnitech создана область `VAKIO` с 15 виртуальными каналами: питание,
  семь режимов и семь скоростей. Сценарии Larnitech могут выбирать каждый из
  них обычным действием над `lamp`.
- Gateway переводит только точные allowlist-адреса области `VAKIO` в raw MQTT
  команды Base Smart. Обратные свежие сообщения синхронизируют селекторы.
- Выбор режима или скорости является самодостаточным действием: gateway
  сначала получает свежее подтверждение включения питания, затем применяет
  режим или скорость.
- Retained-снимки `state`, `workmode` и `speed` сохраняются для диагностики,
  но не считаются свежей телеметрией и не меняют элементы Larnitech.
- Поскольку единственной пользовательской точкой истины является Larnitech,
  панель показывает питание, выбранный режим и скорость по виртуальным каналам
  `407:220`–`407:234`. Доступность самого VAKIO проверяется отдельно безопасным
  MQTT-запросом присутствия `0687` раз в минуту; он не меняет питание, режим
  или скорость прибора.
- Прямое управление VAKIO из HTTP-панели отключено при активном мосте:
  единственная пользовательская точка управления — Larnitech.
- После обновления и перезагрузки ошибочных systemd units нет.
- Список ожидающих APT-обновлений пуст.
- NTP синхронизирован; системный часовой пояс — `Asia/Yekaterinburg` (UTC+5).
- Аппаратный watchdog BCM2835 обслуживается systemd: runtime timeout 1 минута,
  reboot watchdog 2 минуты.
- Persistent journal ограничен 128 MiB и 14 днями, резерв свободного места —
  512 MiB.
- Health timer записывает в `/run/smarthome-gateway-health` загрузку диска,
  доступную память и температуру CPU. Проверенные значения: 25%, 572 MiB и
  42.9 °C; состояние `ok`.
- Ежедневный локальный backup хранится в `/var/backups/smarthome` с правами
  `0700`; архивы имеют права `0600` и срок хранения 7 дней.
- Systemd hardening каркаса gateway имеет оценку exposure `3.0 OK`.
- Gateway держит постоянное WebSocket-соединение с Larnitech API2 и подписан
  на события датчика CO2 `315:36`. Начальная карта читается через
  `get-devices`, изменения — через `status-subscribe`; при разрыве сервис
  переподключается, повторно авторизуется и восстанавливает подписку.
- Реестр панели содержит ровно семь исследованных Larnitech-сценариев. На дату
  проверки `LARNITECH_SCENARIO_CONTROL_ENABLED=true`, а runtime-allowlist
  содержит все семь адресов из реестра. Cooldown равен 30 секундам. Включение
  allowlist проверено без запуска сценариев и без управляющих запросов к API2.

## Локальная панель состояния

Панель открывается в LAN по адресу `http://192.168.1.183/`. Она не содержит
сторонних библиотек, шрифтов и изображений: один статический HTML-файл подходит
для Raspberry Pi 3B+ и продолжает открываться без интернета. Данные обновляются
раз в 10 секунд из `GET /gateway/map`.

Панель показывает:

- свежесть и доступность Raspberry Pi, Larnitech, MQTT и VAKIO отдельно;
- 4 физических модуля Larnitech отдельно от текущего числа адресуемых каналов
  API2 (83 базовых канала и 15 виртуальных каналов VAKIO в `logic.xml`);
- CO2, температуру и влажность комбинированного датчика;
- только фактически подключённый кондиционер AC1, его режим, температуры и
  ошибку;
- состояния основных групп света и двух штор без элементов управления;
- диагностические состояние, режим и скорость VAKIO без обходного управления;
- семь Larnitech-сценариев с адресом, кратким действием и риском; элементы
  запуска активируются только при глобальном флаге и runtime-allowlist;
- ошибки источников и предупреждение об устаревших данных Larnitech.

`observed.read_only=true` в ответе API — явный контракт панели. Исходный полный
массив `larnitech.devices` сохранён в ответе для локальной диагностики, но не
выводится длинной таблицей на главном экране.

## Известные ограничения

- Ethernet не подключён; постоянный шлюз пока зависит от Wi-Fi.
- Помещение комбинированного датчика физически не подтверждено.
- Автоматическая логика по CO2 ещё не включена: подписка Larnitech остаётся
  read-only и не связана с командами VAKIO.
- Управление VAKIO включено отдельно. Для сценариев Larnitech включён точный
  allowlist всех семи исследованных адресов; физическая проверка ни одного
  сценария пока не выполнялась и по-прежнему требует отдельного осознанного
  запуска с наблюдением на объекте.
- Проверенная ревизия Base Smart отвечает на запрос присутствия, но после
  raw-команд не всегда публикует свежие `state`, `workmode` и `speed`. Gateway
  выполняет одну QoS1-публикацию без слепых ретраев и хранит результат как
  `commanded`, отдельно от `confirmed`; при сомнении состояние проверяется
  физически.
- Backup находится на той же SD-карте и предназначен только для локального
  отката конфигурации; для восстановления после отказа носителя нужен внешний
  backup target.
