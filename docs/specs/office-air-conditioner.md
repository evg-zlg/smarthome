# Кондиционер и шлюз ONOKOM в офисе

## Проверенное оборудование

- Внутренний блок: Royal Clima ATTICA NERO `RC-AN22HN/IN`, дата производства
  2023-05-05, изготовитель TCL Air Conditioner (ZhongShan) Co., Ltd.
- Modbus-шлюз: ONOKOM `TCL-1-MB-B`; эта модель соответствует кондиционеру
  `RC-AN22HN` 2023 года.
- Larnitech: модуль `456` (`DW-RS485/DW-RS232/DW-UART`), интерфейс `456:1`,
  `9600/8N2`, Modbus RTU.
- Адрес шлюза Modbus: `1`; подключён один кондиционер (`COUNT_USE_AC=1`).

Ключевые каналы AC1:

| Адрес | Назначение |
| --- | --- |
| `456:249` | основной объект кондиционера |
| `456:237` | признак подключения |
| `456:231` | флаг ошибки |
| `456:230` | текст кода ошибки |
| `456:233` | внутренняя температура |
| `456:235` | температура воздуха внутри |

## Ограничение импортированного драйвера

Установлен импортированный скрипт
`LT-MODBUS-ONOKOM-AIR-TCL-1-MB-B.xXbtV.txt`. Несмотря на
`COUNT_USE_AC=1`, его XML-параметры содержат внешние ссылки для AC1–AC10.
Компилятор Larnitech требует существования всех этих источников.

Поэтому 180 виртуальных служебных элементов AC2–AC10 удалять нельзя. Они не
означают наличие ещё девяти физических кондиционеров. При их удалении сервер
пишет `script has non-existent extern status source`, а при удалении параметров
из элемента `import-script` сам драйвер перестаёт компилироваться. Рабочая
структура модуля `456` содержит 205 адресуемых каналов плюс импортированный
скрипт.

## Инцидент 2026-09-20

Наблюдались две независимые причины неправильного поведения:

1. До очистки температурная автоматика могла включать режим нагрева с
   неподходящей уставкой и затем выключать кондиционер по порогу температуры.
2. После удаления AC2–AC10 появилась отдельная ошибка компиляции драйвера из-за
   отсутствующих внешних источников.

Восстановлены служебные элементы AC2–AC10, при этом активным оставлен только
AC1. Сценарии `456:46` («темпер 1») и `456:47` («темпер») отключены на уровне
конфигурации: интерфейс предлагает действие «Включить».

Физически проверено:

- охлаждение при уставке 24 °C продолжало работать без самовыключения;
- нагрев при уставке 28 °C продолжал работать без самовыключения;
- шлюз оставался подключён, код ошибки — `No error`.

## Наблюдение через Raspberry Pi

Gateway подписан на `315:36` и `456:249`. Бинарное событие AC используется как
сигнал изменения, после чего сервис выполняет `status-get` с подробным статусом.
Панель должна обновлять состояние, режим и уставку без перезапуска сервиса.

## Восстановление

- Полная резервная копия перед очисткой: 2026-09-20 11:58, комментарий
  «Перед очисткой AC2-AC10, Codex 2026-09-20».
- Полная резервная копия перед диагностикой: 2026-09-20 13:29:49, комментарий
  «Перед read-only диагностикой ONOKOM 2026-09-20».
- Предыдущая версия gateway на Raspberry Pi:
  `/opt/smarthome-gateway/app.py.bak-live-ac-20260920`.

При повторении проблемы сначала проверить состояние обоих температурных
сценариев, свежие ошибки компиляции модуля `456`, `456:237`, `456:230` и
`456:231`. Не удалять группы AC2–AC10 без замены импортированного драйвера на
вариант, рассчитанный только на один AC.
